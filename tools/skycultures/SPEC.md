# Sky cultures: shared spec

All agents work against this spec. Each agent owns the files named in its brief and touches no others.

## Layout (served from `apps/web/public/kosmo/static/`)

- `constellations.json`: existing. The 88 IAU constellations plus the `stars` dict. Star id -> `[ra_deg, dec_deg, dist_pc, mag, name, spectral]`. IDs look like `HIP54061`. `dist_pc` can be null.
- `skycultures/<id>.json`: one file per sky culture (new).
- `skycultures/index.json`: manifest, generated by `tools/skycultures/build-index.mjs`.
- `skycultures/boundaries.json`: IAU (Delporte) boundaries.
- `catalog/object-constellations.json`: object id -> IAU abbreviation.
- `skycultures/LICENSES.md`: attribution and licence of every source.

## Culture file schema (`skycultures/<id>.json`)

```json
{
  "id": "chinese",
  "name": "Chinese",
  "region": "East Asia",
  "era": "c. 1000 BCE - present",
  "color": "#e2554b",
  "description": "one or two sentences",
  "source": ["name + URL of each source"],
  "license": "SPDX-ish id and any share-alike note",
  "figures": [
    {
      "id": "chinese-azure-dragon",
      "name": "Azure Dragon of the East",
      "native": "蒼龍",
      "romanized": "Cānglóng",
      "meaning": "short English gloss",
      "kind": "constellation | asterism | mansion | dark-cloud | zodiac",
      "group": "Four Symbols",
      "lines": [["HIP65474", "HIP66249"]],
      "extraStars": {"HIPxxxxx": [ra_deg, dec_deg, dist_pc_or_null, mag, "name", "spectral"]},
      "polygon": [[ra_deg, dec_deg]],
      "iau": ["Vir"],
      "story": "2-4 sentences, factual and sourced, no invented folklore",
      "era": "optional, e.g. 1752-1800 for obsolete IAU-era figures",
      "status": "optional: obsolete | superseded | variant"
    }
  ]
}
```

Rules:
- `lines` is a list of polylines. Each polyline is a list of star ids, consecutive pairs drawn. Same shape as `figure` in `constellations.json`.
- Every id in `lines` must exist in `constellations.json` `stars` or in that figure's `extraStars`. `extraStars` must come from real catalog data (HYG v4.1, Hipparcos). Never invent coordinates.
- `dark-cloud` figures (Emu, Inca llama etc.) have no `lines`. They use `polygon`, a closed outline in RA/Dec degrees, hand-traced from published sources and marked approximate in `story`.
- `color` is a hex colour unique per culture, readable on a dark background.
- Do not invent folklore. If a story is unsourced, leave it short and factual.
- Every figure needs `id`, `name`, `kind`, and at least `lines` or `polygon`.

## Rules for everyone
- Do not commit. Do not run git commands that change state.
- Validate your output with a small script (JSON parses, every star id resolves, ids unique, colours valid). Report counts.
- Record every source and its licence in your culture file, and append a row for it to `skycultures/LICENSES.md` only if the file exists, creating it only if you are the license agent.
- Put scratch files in the scratchpad directory, scripts worth keeping in `tools/skycultures/`.
- If network downloads fail or a source's licence is unclear, say so in your report rather than guessing.

## constellations.json additions

Added by the constellation-data pass (script: `tools/skycultures/enrich-constellations.py`, check with `validate-constellations.py`). The existing shape (`source`, `fetched`, `constellations`, `stars`) is unchanged.

- Top level: `licenses` object (keys `stars`, `distances_added`, `figures`, `text`, `boundaries`, `see`) stating the licence of each kind of content. `source` gained two lines about distance fixes and the story text.
- Every constellation: `story` (3-6 sentences of original text, the last one computed from the real distances of the figure's stars), `origin` (string, e.g. `"Ptolemy"`, `"Bayer 1603"`, `"Lacaille 1756"`) and `year` (integer, the year the figure entered the western tradition in its current form; `150` means Ptolemy's Almagest, c. AD 150).
- Serpens only: `parts`, an array of two objects `{name, latin, abbr, genitive, meaning, part, main_stars, figure}` with `part` = `"caput"` or `"cauda"`. Each `figure` is a list of polylines like the main `figure`. The top-level `figure` of Serpens stays the combined figure (the union of both parts), so consumers that ignore `parts` keep working.
- Invariant: every star id in any `figure` (including `parts`) exists in `stars` with a positive `dist_pc`. Stars whose HYG distance was the `100000` "unknown" sentinel were filled from Gaia DR3 geometric distances (Bailer-Jones et al. 2021); a distance for a very remote supergiant is therefore a statistical estimate with a wide error bar.
